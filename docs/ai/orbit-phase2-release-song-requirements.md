# Orbit Phase 2: 楽曲DB再設計（リリース中心）要件

- Issue: https://github.com/kikun-dev/personal-hub/issues/58
- 更新日: 2026-03-09
- 追補日: 2026-07-02（Issue #129 / #141 / #177 / #207、ADR 0007）、2026-07-24（Issue #425、ADR 0007改訂）、2026-07-26（Issue #427、ADR 0007再改訂）、2026-07-27（Issue #423 / #424 実装完了）

## 背景

既存の楽曲機能（`orbit_songs` 中心）は、今回の要件で必要な「リリース中心管理」「複数リリース再収録」「人物マスタ参照クレジット」「MV/衣装/特典映像」を十分に表現できない。
そのため、Phase 2 の楽曲領域はデータモデルとアプリ層を再設計する。

## 決定事項（仕様確定）

- 楽曲とリリースは M:N とし、中間テーブルでリリースごとの曲順を保持する。
- グループはリリースと楽曲の双方で保持する。楽曲側のグループはフォーメーション割当と一覧表示の基準に使う。
- 人物マスタを新設し、作詞/作曲/編曲/振付/MV監督/衣装担当は人物参照で管理する。
- リリースタイプは `single` / `album` / `best` / `compilation` / `digital_single` / `other`。
- ナンバリングは `single` / `album` のみ必須（整数）。`best` / `compilation` / `digital_single` / `other` では未設定必須。
- 楽曲時間は現行モデルでは保存しない（`duration_seconds` は Issue #141 で廃止）。
- 楽曲には単一ラベル（表題/選抜/アンダー/全員/ソロ/ユニット/期別、任意）を保持する。
- 選抜/アンダー/期別と列は楽曲ラベル・フォーメーションから導出し、リリース×メンバーで手動保持する情報は福神/休業中 overlay に限定する。センターの正典は、2026-07-24のADR 0007改訂で楽曲参加メンバーへ変更した。
- MVは「存在する場合リンク必須」。監督/ロケ地/配信日/メモは任意。
- MVとは別に、楽曲関連動画（Dance Practice/ひなリハ、コール動画）を保持する。監督は持たず、URL必須・配信日/メモ任意とする。
- MV/関連動画に配信日がある場合、トップの月カレンダー/選択日/今日はなんの日へ動画配信イベントとして合成表示する。
- アートワーク・特典映像・MV・衣装は未設定可（空配列/NULL可）。
- 画像（リリースアートワーク、衣装画像）は Supabase Storage object path で保存する。
- 既存 `orbit_songs` 系は移行せず、置換（ゼロ再構築）する。

### 2026-07-24改訂（Issue #425 / ADR 0007）

初期要件ではフォーメーションメンバーを楽曲固有の参加者として扱い、リリース参加メンバーを割当可能な集合としていた。部分情報を段階的に登録するため、次の方針へ改訂する。

- 楽曲参加メンバーとセンターを `track_members` でフォーメーションから独立管理する
- フォーメーションは任意とし、存在する場合は楽曲参加メンバー集合と完全一致させる
- センターは楽曲参加メンバー内の最大2人とし、フォーメーションがなくても登録できる
- フォーメーションが存在する場合、センターは1列目に含める
- リリース参加メンバーは候補の優先表示と不一致警告に利用するが、楽曲参加メンバーの許可集合にはしない
- `release_members` はリリース全体の参加者・休業情報として独立管理し、楽曲参加メンバーの和集合から自動導出しない

この改訂は初期要件の完了状態を変更せず、後続Issue #426 / #427でデータ基盤と楽曲管理を移行した。ライブ連携は #423 / #424で対応済み。

なお、リリース参加メンバーとの関係は2026-07-26の再改訂で置き換えた。下記を参照。

### 2026-07-26再改訂（Issue #427 / ADR 0007）

楽曲参加メンバーの範囲を初出リリースの参加メンバーに限定し、不一致を許容しない方針へ変更する。

- 楽曲参加メンバーは、その楽曲の初出リリース（最も古い非nullのリリース日を持つ紐づきリリース。同日はリリースIDで決定的にタイブレーク）の参加メンバーから選ぶ
- アルバム・再録など後続リリースの参加メンバーは候補に含めない。後続リリースへの収録は既存楽曲の再掲であり、楽曲参加メンバーやフォーメーションを変更しない
- 不変条件は `楽曲参加メンバー ⊆ 初出リリース参加メンバー` とし、初出リリース参加メンバー外の登録は許容しない。両集合の完全一致は要求しない（1つのリリース内で楽曲ごとに参加者が異なるのは正常）
- 日付が設定された紐づきリリースが1件も無い場合、初出リリースは未確定として扱い、参加メンバーの候補を提示しない。紐づく全リリースの参加者へフォールバックしない
- 候補の範囲内では、楽曲と同じグループのメンバーを優先表示する。候補に含まれる他グループのメンバーも選択でき、グループ外選択時の警告は維持する
- 不変条件はアプリケーション層（管理UIの候補提示と、楽曲保存境界のサーバー側検証）で強制する。DBのハード制約は #426 で撤去した状態を維持する
- 楽曲側の保存境界だけでは、リリース日・収録曲・リリース参加メンバーの変更によって事後的に生じる不一致を防げない。初出リリースのDB上の明示的な関連化とDB制約の再導入を含め、Issue #432 で扱う

## 必須/任意

### リリース

- 必須: `title`, `group`, `type`
- 任意: `numbering`（ただし `single/album` では必須）, `releaseDate`, `artworkPath`, `bonusVideos`, `participants`

### 楽曲

- 必須: `title`, `release紐付け`
- 任意: `label`, `generation`, `participants`, `center`, `formation`, `credits`, `mv`, `videos`, `costumes`

## 機能要件

### 1. リリース管理

- リリースごとにタイトル、グループ、タイプ、ナンバリング、リリース日を管理できる。
- 版種ごとの特典映像を複数行で管理できる（例: Type-A, Type-B）。
- リリース参加メンバーを複数選択できる。
- リリース曲目アートワークを保持できる。

### 2. 楽曲管理

- 楽曲は1件以上のリリースに紐づく。
- リリースごとの曲順（トラック順）を保持できる。
- 楽曲ごとのグループとラベルを保持できる。
- 作詞/作曲/編曲/振付を役割ごとに複数人登録できる。
- MVと関連動画（Dance Practice/ひなリハ、コール動画）を登録できる。
- 衣装を複数登録でき、衣装ごとに担当者と画像を保持できる。

### 3. フォーメーション

- 列数と列ごとの人数を設定できる。
- 楽曲参加メンバーは初出リリースの参加メンバーから選択する。候補の範囲内では同グループのメンバーを優先表示し、他グループのメンバーも選択できる（2026-07-26再改訂）。
- 列ごとの人数設定と割当メンバー数は一致必須。
- フォーメーションは未設定可。設定する場合は、全列のメンバー集合を楽曲参加メンバー集合と完全一致させる（2026-07-24改訂）。
- 選抜/アンダー/期別と列はフォーメーションと楽曲ラベルから導出し、センターは `track_members` を正典とする（2026-07-24改訂）。
- 福神/休業中はフォーメーションだけでは判断できないため、リリース×メンバーの overlay として保持する。
- 櫻坂46 1st〜5th Single の櫻エイト期は、`label = title` の代表トラックを基準に特別ルールで導出する。

### 4. MV

- MVあり/なしを管理できる。
- MVありの場合はリンク必須。
- 監督、ロケ地、配信日、メモは任意。

### 5. 関連動画

- 関連動画の種別は `dance_practice` / `call`。
- `dance_practice` は櫻坂46で「Dance Practice」、日向坂46で「ひなリハ」と表示する。ラベルが解決できないグループでは表示対象外にする。
- `call` は「コール動画」として表示する。
- 関連動画ありの場合はリンク必須。配信日、メモは任意。
- 収録曲には MV / Dance Practice・ひなリハ / コール動画の有無をバッジ表示する。
- 配信日がある MV/関連動画は、トップの月カレンダー/選択日/今日はなんの日に「曲名（種別）」で表示し、リンクは動画URLへ外部リンクとして開く。

## データモデル方針（論理）

- `releases`: リリース本体
- `tracks`: 楽曲本体
- `release_tracks`: リリースと楽曲の中間（曲順を保持）
- `people`: 人物マスタ（表示名）
- `track_credits`: 楽曲クレジット（role + person）
- `release_members`: リリース参加メンバー
- `release_member_positions`: リリース×メンバーの選抜ポジション overlay（福神/休業中）
- `track_members`: 楽曲参加メンバーとセンター（2026-07-24改訂、Issue #426で追加予定）
- `track_formations` / `track_formation_members`: フォーメーション列定義と割当
- `track_mvs`: MV情報
- `track_videos`: 楽曲関連動画
- `release_bonus_videos`: 特典映像
- `track_costumes`: 衣装情報

注: 物理テーブル名は既存 `orbit_` 命名規則に合わせて実装時に確定する。

## 画面スコープ

- Admin: リリース/楽曲の一覧・作成・編集・削除（関連子要素含む）
- Public: 一覧/詳細（リリース情報、楽曲詳細、フォーメーション表示）

## 非対象（Non-goals）

- 既存楽曲データの移行
- ライブ/セットリスト実装
- 匿名公開向けRLS方針変更

- 必須項目と制約（タイプ別ナンバリング、MVリンク、フォーメーション整合）が検証される。
- `pnpm --filter oshikatsu-web typecheck` と `pnpm --filter oshikatsu-web lint` が通る。
